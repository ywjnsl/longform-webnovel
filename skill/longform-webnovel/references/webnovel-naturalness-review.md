# 网文自然度强制审稿

## 目的

每次新写或修改章节正文后，都用本模块做一次独立的网文自然度审稿。它检查影响沉浸、人物可信度和阅读余韵的可观察文本模式，不判断作者身份，不输出 AI 概率，也不以“像不像人工”为无限优化目标。

**这是章节门禁，不是按需润色。** 哪怕只改一句、`prose_lint.py` 没有 finding、编辑与读者模拟已经通过，正文哈希变化后仍必须重做本审稿。作者要求“直接交稿”可以阻止无证据润色，不能跳过审稿。

需要建立个人声音或执行定向修改时，同时读取 [prose-naturalization.md](prose-naturalization.md)。

## 输入与视角

审稿者读取当前完整章节、`canon/style-profile.md`、必要正史和最近 2–5 章已确认正文。先运行 `repetition_audit.py`：番茄短故事比较全部已提交前文，长篇默认比较最近 5 章。再以目标网文读者身份顺读，记录哪里产生“作者在安排我怎么理解”“角色在播设定”“每一步都过于刚好”等体验；最后回到编辑视角定位逐字证据。

不要先看 `prose_lint.py` 的结论再决定读者感受。扫描结果只能用于复核遗漏，不能替代语义审稿。重复审计是防止漏掉确定性回声的独立门禁，也不判断作者身份。

## 十二类模式

| 类别 | 形成问题簇的证据 | 常见读者代价 | 定向方向 |
|---|---|---|---|
| `echo-repetition` | `repetition_audit.py` 报告长句逐字重复或高相似复述，且当前场景没有逐字确认、刻意复沓等必要功能 | 读者误以为段落被重复粘贴，信息没有推进 | 删除回声、合并信息，或让第二次出现产生不同反应与后果 |
| `modifier-overuse` | 相邻句密集使用多种强度、时间或态度副词，持续代替人物特有动作 | 节奏被统一标注，动作和声音趋同 | 只处理证据簇；保留必要副词，把其余压力落到动作与选择 |
| `rhetorical-symmetry` | 同一小段连续出现不同类型的对仗、回环或成组金句 | 角色像在替作者产出摘要，场景余波被封口 | 保留符合人物利益的一处，拆掉承担总结功能的工整句 |
| `cadence-packaging` | 两组以上“短动作—对白—解释结论”以相同节拍复现，或连续大量独句成段、段末补战术说明 | 阅读反应被预包装，场景像提纲逐项落地 | 把同一次交锋并回一段，删掉动作后的字幕，让他人反应直接造成后果 |
| `over-explanation` | 动作、对白或场景已证明后，旁白再次解释人物判断、关系意义或事件结论 | 情绪被预先说明，读者没有参与理解 | 删除重复判词，或让必要信息落到动作与后果 |
| `corrective-syntax` | “不是……而是……”“没有……只是……”等纠正式骨架连续承担金句或总结功能 | 叙述者持续校正读者，声音显得统一而用力 | 保留真正的认知转折，改写重复骨架 |
| `expository-dialogue` | 角色向本来知情的人完整讲规则、背景、证据或标准反驳 | 人物像设定播报器，对话失去利益和回避 | 缩到角色此刻愿意说的部分，让信息从反应中露出 |
| `same-voice` | 多名角色共享相同的冷静程度、词汇、句长、机锋和总结能力 | 人物只能靠名字区分 | 从各自利益、恐惧和回避方式重做命中对白 |
| `over-engineered-causality` | 多个物件、回忆、规则与巧合都立即服务同一钩子，人物没有独立选择造成的摩擦或余波 | 场景像预先装配的提纲，世界只为主角让路 | 不拖慢主线；让一项信息延迟、失败或产生真实选择代价 |
| `generic-reaction` | “眼前一黑、眯起眼、嘴角一勾、深吸一口气”等通用反应或电影式转场成组替代身体过程 | 人物身体与场景失去具体性 | 改为会改变动作、距离或判断的身体反应 |
| `theme-closure` | 可见后果或情绪已经落地，结尾又概括主题、成长或真正意义 | 余韵被封口，读者被告知应该怎样感受 | 停在行动、物件、关系变化或未回答的问题上 |
| `padding-expansion` | 为凑字数、过检测或“增加生活感”新开无关场面、回忆、电话、家具巡游或第二现场 | 主线被稀释，读者感到注水 | 整场删除；不把注水改写成另一套功能金句 |

商业网文的快节奏、倒计时、章尾钩子和常用句式本身不是问题。整章独句成段、每段都做成功能金句，才是问题簇。只有同类证据形成模式簇，并造成具体读者代价时才写 finding。孤立单句只进入复核，不为了填报告强行修改。

## 审稿与修改

1. 记录初审正文 SHA-256。
2. 先处理重复审计：没有功能的重复应修订；确需保留的每个 exact/near finding 都要写入哈希绑定的 `repetitionExceptions`，给出具体编辑理由。再顺读并按十二类模式列证据簇；每项必须说明 `readerCost` 和只影响命中段的 `direction`。长篇还要检查是否整章独句成段、动作后补战术字幕，或为凑字新开场面。
3. 无成立问题簇时标记 `pass`，`revision.action` 为 `not-needed`，不得继续寻找理由润色。
4. 只有轻微、可保留的风险时标记 `pass-with-notes`。未解决的高优先级问题不得放在此状态蒙混通过。
5. 影响沉浸、人物或收尾且需要修改时标记 `needs-revision`，按 [prose-naturalization.md](prose-naturalization.md) 最多自动定向修改一次。不得整章重新生成，不得把标红段改成更短更工整的功能金句，也不得为自然化新增场面。
6. 修改后重新运行章节指标、重复审计、语言扫描、本审稿、编辑审稿和读者模拟。最终报告只引用修改后仍存在的逐字证据；已经删除的问题写入 `revision.changedCategories`，并用 `beforeTextSha256` 记录修改前版本。旧重复报告与旧例外随正文哈希一并失效。
7. 复审仍为 `needs-revision` 或仍有未解决的 `high` finding 时阻断提交。作者明确接受风险时，使用 `author-approved` 并关联 `state/decisions.json` 中已确认的 `naturalness-exception` 决策；该决策必须绑定本章章号与最终正文 SHA-256，不能复用无关决策。

## 报告结构

将结果写入 `reviews/第NNNN章-review.json` 的 `naturalness` 对象：

```json
{
  "status": "pass",
  "diagnosis": "未发现影响沉浸的自然度问题簇。",
  "reviewedTextSha256": "最终章节正文 SHA-256",
  "findings": [],
  "repetitionExceptions": [],
  "revision": {
    "action": "not-needed",
    "notes": "没有证据支持额外修改。"
  }
}
```

确需保留重复 finding 时，`repetitionExceptions` 使用：

```json
{
  "findingId": "重复报告中的稳定 finding id",
  "reason": "人物在质询中逐字要求证人确认原话，第二次出现会改变证词效力。",
  "reviewedTextSha256": "最终章节正文 SHA-256"
}
```

理由必须说明重复在当前场景承担的功能。“为了节奏”“作者喜欢”或“检测器可能误报”不够具体。任何未处置的 exact/near finding 都阻断提交。

执行过修改时使用：

```json
{
  "status": "pass",
  "diagnosis": "解释过满问题已处理，复审未见残留问题簇。",
  "reviewedTextSha256": "修改后章节正文 SHA-256",
  "findings": [],
  "revision": {
    "action": "revised",
    "beforeTextSha256": "修改前章节正文 SHA-256",
    "changedCategories": ["over-explanation"],
    "notes": "删除重复结论，以人物动作保留必要因果。"
  }
}
```

仍保留的 finding 使用：

```json
{
  "priority": "low",
  "category": "corrective-syntax",
  "evidence": ["当前最终正文中的逐字片段"],
  "readerCost": "具体说明读者体验损失",
  "direction": "只针对证据段的修改方向",
  "resolved": false
}
```

`evidence` 只能引用最终正文中的逐字子串。修改前已删除的句子不得伪装成最终证据，也不把审稿意见本身写进正文。

自然度风险例外的决策至少包含：

```json
{
  "id": "accept-naturalness-risk-0016",
  "status": "confirmed",
  "kind": "naturalness-exception",
  "chapter": 16,
  "reviewedTextSha256": "最终章节正文 SHA-256"
}
```

## 朱雀逐段证据

作者提供朱雀逐段标红、导出报告或截图时，可以把原始标注转录到审稿 JSON 顶层的 `externalNaturalness`。它只帮助编辑定位段落，不是作者身份结论，也不能替代重复审计或自然度审稿：

```json
{
  "provider": "zhuque",
  "checkedAt": "2026-09-06T10:00:00+08:00",
  "reviewedTextSha256": "送检正文 SHA-256",
  "overallSignal": "逐段报告已提供",
  "sourceArtifacts": ["reviews/evidence/朱雀-第0016章.png"],
  "flaggedPassages": [
    {
      "text": "从送检正文逐字复制的标红片段",
      "location": {"paragraph": 12},
      "externalLabel": "原报告标签",
      "editorDiagnosis": "over-explanation",
      "action": "revised",
      "resolved": true
    }
  ]
}
```

截图保存在项目 `reviews/evidence/`。哈希不匹配、截图缺失或标红文字不在当前正文时只产生诊断警告；应重新对应当前版本，不能凭总体百分比或无法匹配的高亮自动改稿。是否修改仍取决于逐字证据、人物功能和读者代价。

作者提供逐段标红后，按 [prose-naturalization.md](prose-naturalization.md) 的朱雀段落合同执行：`kept` 表示该段冻结或有功能保留，`revised` 表示就地改写同一动作，`deleted` 表示整段删除，`rejected` 表示标红无法对应可观察文本问题、只作备注。禁止把 `action` 理解成扩写或另起场面。

## 禁止事项

- 不用错别字、病句、随机断句、方言或无功能闲聊制造人味。
- 不一刀切删除副词，不强制加入迟疑、误解、零头数字或无功能物件，也不优化句子数与句长方差。
- 不把整章切成独句金句墙，不在动作后补“他要的就是……”这类战术字幕，不把每个物件都做成当章伏笔。
- 不把任何单词、句长指标、短段数量或扫描命中当成作者身份证据。
- 不为自然度牺牲因果清晰、类型回报、世界规则或已确认的个人声音。
- 不因作者要求停稿而跳过审稿；若无成立问题，审稿结论就是 `pass`，无需修改。
- 不做第二轮无证据润色。一次定向修改后仍有阻断问题，报告并停止提交。
- 不为凑 2500 字或提高过检比例新增场面。仍不过就停，把选项交给作者。
