# 番茄出戏与前后一致（写作与审稿）

把平台公开的「质感/出戏」课转成可观察检查。本课系列还预告了重复、基础错误、中后期下滑、人物不立体等后续问题；那些未开课时，分别走已有自然度、行文、连续性和 [fanqie-character-craft.md](fanqie-character-craft.md)，不要假装本文件已经覆盖。

本模块依据番茄小说网作家课堂 2026-08-12《告别“出戏感”：写出让读者上头的质感网文》。当前只落地其中正在讲解的第一题：**前后内容不一致，逻辑衔接较弱**。平台口径可能调整；作者提供更新课时以更新页为准，不整段搬官方例文。

适用：每次写章或审稿默认执行。与签约、人物、新书抓人文件一起用：那些管能不能签、人是不是活人、开篇能不能留人；本文件管读者会不会因为对不上而瞬间出戏。

系列开头说的「文风呆板」（通顺却像说明书、该哭却干巴）走自然度 `rhetorical-symmetry` / `over-explanation` / `generic-reaction`，不是本课正文。本课正文是：**时间线、设定、人设任何一处对不上，质感先崩。**

## 三种出戏，对上现有文件

| 出戏 | 正文长什么样 | 审稿维度 | 正史落点 |
|---|---|---|---|
| 设定矛盾 | 战力天花板被轻松跨过；技能效果前后两套；金钱数量级无积累地跳；珍品变街货；规则只绑配角、主角自动豁免 | `continuity` / `causality` | `canon/laws.md`、`canon/world.md` |
| 情节矛盾 | 昼夜季节对不上；无赶路就换城；规定的先后顺序写反；仇人无过渡称兄；关键人或物无铺垫救场 | `causality` / `structure` | `canon/timeline.md`、`state/story-state.json` |
| 人设矛盾 | 高智商角色为爽点降智；语气习惯骤变；名字身份写错；配角台词可互换、只剩吹捧送宝 | `character` / `continuity`；自然度 `same-voice` | `cast/{id}/SKILL.md`、`state.json` |

## 方法一：设定先查库，再写冲突

写到战力对比、花钱、违禁、门派规矩之前，先读 `canon/laws.md` 与 `canon/world.md`。对不上就改这一拍，或让角色付出违例代价；禁止为过情节让规则对主角失效。

典型失败（用本书自己的原文当证据，不套用他人例子）：

1. **战力**：前期把对手写成打不过，后期一次升级轻松碾压，再凭空加更强敌人把铺垫清零；或「此招必死」后面只蹭破皮。
2. **经济**：穷到计数的钱，几章后甩出两个数量级且无积累过程；天价物件变成随便掉落。
3. **规则**：明文禁止的事，主角反复做却无人执行；同一条规矩只用来卡住配角。

新设定、新道具、新规则写进正文后，必须在同一次提交里更新法则库。后期确要改上限，只能用剧情打补丁（揭示更大范围、例外有代价），并记入法则与时间线；禁止默默换规则。

升级必须同时增加代价、责任、限制或新的对抗方式。见基本原则第 6 条与 [reward-system.md](reward-system.md)。

## 方法二：时间线记节点，章纲对上写前卡

不要只在脑子里记时间地点。`canon/timeline.md` 只记推动故事的节点：情节转变、角色状态变化、时间或地点跳跃。平铺过渡不记流水账。

每章提交时补一行：故事时间过了多久、人在哪、伤/钱/关键物有什么变化。多线并行时，同一时间点上不同角色的位置必须能并排核对；对不上就是瞬移。

换场必须有身体过程，见 [scene-craft.md](scene-craft.md)。禁止上一场还在甲地、下一场无过渡站在乙地。

公开课的章纲四要素对上已有写前卡，不另开一套大纲：

| 四要素 | 写前卡对应 |
|---|---|
| 本章目标 | 当下欲望 + 进入场景时已有的问题 |
| 冲突 | 主要阻碍 |
| 转折 | 至少一项真实状态变化（可失败） |
| 结尾钩子 | 结尾推动力 |

阶段大目标拆成 3–9 个互不重叠的子问题，放进 `planning/current-arc.md` 与滚动章纲。子问题决定这段要解决什么，写前卡决定这一章怎么写。禁止为制造冲突让角色做完他不会做的事，再靠空降人物或道具解围。

## 方法三：动笔前对齐人设，降智先改剧情

有名字、有戏份的角色必须有人物卡。重大决策和对白前问：按此人经历、智商、边界，他真的会这样说、这样做吗？

答案是「不会，但剧情需要」时，改阻碍或信息，不改人。详见 [fanqie-character-craft.md](fanqie-character-craft.md)。

写完对白再问：换另一个角色说是否同样成立？成立则 `same-voice`。配角不得集体变成只会吹捧主角的背景板；`anchor` / `recurring` 仍要有自己的立场，见 [supporting-cast.md](supporting-cast.md)。

名字、称呼、身份以 `canon/characters.md` 与角色卡为准，写后核对，禁止张冠李戴。

## 写节与审稿必答

`editor.diagnosis` 的 `continuity` / `causality` 用一两句覆盖：

1. 本节战力、金钱、规则有没有跟法则库打架？主角有没有免费豁免？
2. 时间地点伤势能否接上时间线？有没有瞬移或顺序写反？
3. 有没有为爽点让角色降智，或让配角台词可互换？
4. 新设定有没有写进法则库和时间线？

`moments` 必须引用对不上的前后原文，不能只写「有点出戏」。读者若指出说明书腔、该哭却干，另走自然度，不要用本文件的设定检查代替。
