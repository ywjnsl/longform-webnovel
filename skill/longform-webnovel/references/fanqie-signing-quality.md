# 番茄签约质量（写作与审稿）

把平台公开的签约评估标准转成可观察检查，用来写正文和审稿。不是法律意见，不保证能签约，也不把「像不像 AI」当成检测结论。

本模块依据番茄小说网 2026-09-07《番茄小说作品签约标准说明》（作家课堂公开页）。平台口径可能调整；写稿前若作者提供更新说明，以更新页为准，并改本文件的日期与要点，不凭记忆扩写官方原文。

适用：`fanqie-short-story` 的写节、审稿、完结终审默认执行。`serial` 在作者按番茄投稿/签约来写时同样执行。其他平台只借用「不注水、不套结构、不烂尾」三条，不把番茄签约结果说成通用定律。

## 两层，不要混

| 层 | 过了代表什么 | 不过时做什么 |
|---|---|---|
| 进评估 | 基本可读、权属/尺度合规、情节能推下去 | 阻断提交或标记 `blocked`，先修 |
| 优先签约 | 有辨识度、立意贴着人物矛盾、能量住阅读、短故事则收口完整 | 记入编辑诊断；不假装一定能签 |

与人物立体、情绪硬喊、无代价胜利、新人难认相关的检查，见 [fanqie-character-craft.md](fanqie-character-craft.md)。

热门题材、字数达标、过了基础质量，都不等于优先签约。

## 合规：写成检查，不写成骂人

以下只认正文里能指出来的问题。不得把扫描结果、句长或「AI 味」说成身份鉴定。

写或审时逐项问，命中则必须有逐字证据：

1. **权属与套用**：人物专名、独特物件、事件链、核心场面是否直接搬自参考稿或作者已删旧作？按 [reference-adaptation.md](reference-adaptation.md) 与 `story_overlap.py` / `reference_guard.py` 处理。直接套别人的人物设定、故事结构和核心剧情，视为结构套用，不能靠换名过关。
2. **注水拉长**：有没有为凑字、过检或「增加生活感」而重复堆砌、机械扩写、大段不推动情节的铺陈？对应自然度 `padding-expansion`。合法加厚只加已起手动作的中间过程。
3. **空转与水文**：有没有格式混乱、结构失常、大段不改状态的说明？对应空转非法：本章/本节必须改变至少两个状态维度。
4. **逻辑与人物**：前后事实是否矛盾？人物这一拍的行为是否违背其已知信息、当场利益或已裁定意图？对应编辑维度 `causality` / `character`。
5. **不推动情节的大段**：删掉后主线、人物选择和代价都不变的段落，优先删。

## 优质：写前就要用，不要等终审才补

写节前和编辑审稿时用同一张清单。短故事不必强行满足「长篇 IP 延展」；把「发展潜力」读成：主线清晰、前后质量不塌、收口完整。

| 检查 | 写正文时怎么落地 | 审稿时怎样才算过 |
|---|---|---|
| 主线与开篇 | 本节入口就要让人看见当前冲突；不在节首回顾设定 | 冷读者能说清谁在做什么、会失去什么 |
| 节奏与递进 | 中段由上一行动造成更难局面，不平行加事 | 没有无后果反转、没有同一功能场面复制 |
| 人物动机 | 上场角色按隔离意图行动；配角有自己的要价 | 关键选择能从欲望、恐惧、信息解释，不是为了作者方便 |
| 情绪反应 | 压力落到身体、距离、物件和代价，不靠旁白硬喊 | 读者 moments 能指出具体反应句，而不是情绪标签 |
| 创新辨识 | 合同里的独特机制必须真正运行，不能只写在标题里 | 机制造成不可逆选择或代价；换掉该机制则故事塌 |
| 立意 | 立意只通过人物选择显现，不另开作者总结段 | 不是停在「善恶/逆袭」口号；也不是段末哲理金句 |
| 文字完成度 | 场面有空间和过程；病句、空洞对白按风格档案修 | 通顺、少口水；爽点来自选择后果，不靠旁白宣布 |
| 完整不烂尾 | 见下一节 | 主承诺兑现，且最后一场已起手的动作做完 |

## 收口：金句封口和动作截断都非法

平台要「情节完整不烂尾」。本 skill 同时禁止主题金句收口。两者冲突时，**先做完最后一场动作，再停在可见后果上**。

| 问题 | 自然度类 | 证据长什么样 | 改法 |
|---|---|---|---|
| 主题封口 | `theme-closure` | 后果已落地，又写「真正重要的是……」「我没有得到……我得到的是……」 | 删总结句，保留物件、动作或未回答的次级问题 |
| 动作截断 | `truncated-ending` | 最后一场已经起手（方子递上、门开了、钱打下了），只写半句功能句就停 | 只把该动作的过程写完；不另开现场、不加金句 |
| 注水续摊 | `padding-expansion` | 矛盾已解决，又新开无关回忆、第二现场、天气巡游 | 整场删除 |

禁止用「避免主题金句」当截断理由；禁止用「写完收口」当注水理由。

短故事标记 `complete` 前，终审 `endingBoundary` 必须同时确认：主承诺已兑现；最后一场动作已完成；没有主题金句；没有续作主钩。

## 编辑诊断必答（番茄短故事每节）

写 `reviews/第NNNN章-review.json` 的 `editor.diagnosis` 时，用两三句覆盖下面四问，不要另造分数：

1. 本节哪一段如果删掉也不影响状态变化？（没有就写「未发现空转段」）
2. 人物关键行为是否对得上其意图和已知信息？
3. 独特机制有没有在本节真正运行？
4. 若是最后一节：最后一场动作是否做完，有没有金句封口？

命中注水、套结构、空转、截断收口时，编辑 finding 使用维度 `padding`、`originality`、`structure` 或 `ending`，优先级不够高不得标 `pass` 混过。截断收口至少 `medium`；主承诺未兑现或大段不推情节为 `high`。

读者模拟若觉得「像没写完」「后面在凑字」，必须把原文片段写入 `moments`，不能只在诊断里概括。

## 常见借口

| 借口 | 处理 |
|---|---|
| 「短章合法，所以半句收口也合法」 | 短章合法，未完成的最后一拍不合法 |
| 「字数低于目标，再开一个药店/回忆」 | 低于目标不是开第二现场的许可 |
| 「平台打 AI 粗制滥造，先过检测」 | 只修可观察的注水、空转、套结构和截断；不做身份鉴定 |
| 「热门题材能签」 | 题材不替代机制运行、人物动机和完整收口 |
| 「基础可读就够完结」 | 够进评估不够自动完结；短故事仍要主承诺兑现且不烂尾 |
