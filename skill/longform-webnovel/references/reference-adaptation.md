# 参考短故事再创作

## 目标与边界

用户说“仿写”“照这个写一篇”“换题材重写”时，先把参考稿转成抽象机制，再创作独立的新故事。可以迁移的是读者体验和可描述手法，不是原作的表达与识别性组合。

默认不做以下内容：

- 换人名、地点或职业后复述同一事件链；
- 按原段落顺序逐段同义改写；
- 复用人物专名、独特物件、专有设定、证据链、关键场面、结局揭示或标志性句子；
- 以“爆款结构”为名保留原作大部分因果节点；
- 直接模仿在世作者的个人声线。作者风格请求按 [style-system.md](style-system.md) 转成高层参数。

若用户明确说明参考稿是本人作品或公版文本，并要求改编、续写或重制，先记录允许保留的具体元素；未获明确允许的部分仍按默认边界处理。

## 输入与来源

接受用户粘贴的文本、工作区文件或可合法访问的公开页面。来源缺失时只询问参考稿或路径，不先猜它的结构。不要默认把完整参考原文复制进项目；在 `research/reference-adaptations/` 保存来源标题、作者或页面、访问日期、用户声明的权利范围，以及下面的机制卡即可。

参考稿很长时先完整阅读与当前任务有关的部分。无法取得全文时明确样本范围，不把局部观察写成整篇规律。

## 两张卡

先输出“可迁移机制卡”：

- 点击承诺：标题和第一屏让读者期待什么；
- 主情绪：求生、复仇、身份翻转、关系确认或其他主要回报；
- 主角发动机：压力、主动选择、代价和短期目标如何相连；
- 冲突机制：双方为何不能同时得利，制度、资源或关系怎样制造限制；
- 信息与回报：关键揭示和回报位于全文的大致比例及其功能，不复述具体场面；
- 叙事参数：人称、叙事距离、句式节奏、对白功能、信息密度和场景转换；
- 有效原因与失控风险：哪些机制服务读者，照搬表面形式会怎样失败。

再输出“创作隔离卡”：

- 可以保留：题材大类、抽象关系类型、情绪曲线、回报密度等通用元素；
- 必须替换：所有专名、独特物件、专有规则、标志性措辞和可识别场面；
- 必须重建：主角核心欲望、冲突发动方式、解决机制，以及决定结局的因果；
- 禁用词：参考稿中的人物名、地名、组织名、独特物件名和自造概念，供脚本检查。

## 从机制到新故事

1. 先改变冲突发动机和决定结局的因果，再选择新题材、人物关系与世界规则；只换背景不算新故事。
2. 用新人物的欲望和限制重新生成事件。若删除参考稿后某一场仍只能按原顺序发生，说明隔离不足。
3. 书名、前 300 字和试读节点围绕新故事自己的承诺设计，不拿参考稿标题做句式模板。
4. 将新合同与隔离卡一起交给作者确认，再按 `fanqie-short-story` 流程建项和写作。
5. 写作时只看机制卡、新故事合同和当前项目正史，不逐段对照参考原文。

## 复用检查

每节或全文完成后运行：

```bash
python3 <skill-dir>/scripts/reference_guard.py \
  --source <参考稿.md> \
  --candidate <候选正文.md> \
  --forbid-term <人物名> \
  --forbid-term <独特物件名>
```

脚本默认把连续 60 个有效文字单元或候选 12-gram 命中率达到 12% 标为高风险，把连续 30 个单元或命中率达到 5% 标为中风险。阈值是本地编辑筛查参数，不是平台规则、抄袭认定或法律标准。高风险时针对命中项自动重写一次并重跑；第二次仍为高风险就停止交付正文，向作者报告需要重建的部分。低风险也不代表结构必然原创，仍需按隔离卡人工检查事件链、解决机制和结局因果。

项目建成后再运行 `story_overlap.py`，防止新稿虽然避开参考原句，却复用了作者自己已有项目的人物和故事发动机。

## 面向作者的交付

正文前只展示必要结果：参考稿的可迁移机制、明确舍弃的识别性元素、新故事的一句话承诺与核心变化。不要大段复述参考原文，也不要以“相似度低”承诺作品绝对原创或必然通过平台审核。
