# 章节细纲

章节细纲是写前卡的执行层。写前卡回答“这一章为什么存在”，细纲回答“这一章按什么场景拍把因果走完”。它用于防止正文过早结束后靠重复对白、解释或无关场面补字，不是把正文写成分镜脚本。

## 何时必须填写

`serial` 每章必须填写；`fanqie-short-story` 每节必须填写。相邻章节有强因果依赖时，先根据上一章实际发生的结果重排细纲，不能沿用旧草案。

## 最小结构

普通章节通常列 3–5 个场景拍；打斗、追逐、调查、经营或多人博弈等动作密集章节可拆成更多拍，但每拍都要改变行动条件。每拍写六项：

1. **入口与当下动作**：人物从哪里、带着什么问题进入，先做什么；
2. **本拍目的**：推进冲突、揭示信息、迫使选择或兑现等待中的回报，至少命中一项；
3. **阻碍与反应**：谁/什么阻止，阻碍如何具体发生，人物如何应对；
4. **转折与代价**：行动怎样改变局面，失去什么、暴露什么或承诺什么；
5. **状态落点**：目标、关系、认知、资源/能力、世界局势、道德位置中哪一项发生变化；
6. **离场条件**：什么结果让本拍结束，并把什么未决问题交给下一拍。

可附一个**篇幅参考**：预计占本章的约四分之一、三分之一或一半，并标明这一拍详写还是略写。只用于防止某个关键动作被一句话带过，不把每拍字数当硬指标。细纲不写对白原句和景物清单。

每一拍是一个信息团：用一句话能说清它改变了什么。两个互不服务的信息团不要塞进同一拍；删掉后因果不变的那一个，删掉。卷里的矛盾是「谁要阻止这件事完成」；这一拍的冲突是有人正在阻止主角拿到他此刻要的东西。只有对立、没有人动手，这一拍还没成立。

## 事件跨度与本章职责

在细纲顶部先标注：

- **事件跨度**：`single`（本章完成）、`opening`（开端）、`middle`（推进/升级）、`turn`（中段翻转）或 `closing`（收束）；
- **事件线 ID**：对应 `state/threads.json` 的剧情线；跨章事件必须写明预计在哪个窗口兑现；
- **本章交付**：本章真正完成的局部目标、代价或认知变化；不要把事件最终答案提前写死。

跨章事件可以按“触发 → 试图解决 → 受阻/升级 → 改变条件 → 收束”分布在多章。`middle` 或 `turn` 章节只需让行动条件发生不可逆变化，不能为了形成完整故事而替角色解决后续问题。第 3、5 章的回报也可以是阶段性优势、有效线索、关系让步、失败代价或新限制；它们必须改变状态，但不等于整条事件线结案。

## 结尾不强制悬念

章节可以用以下任一自然落点结束：当前动作完成、选择已经做出、代价已经落地、场面被迫中断、认知刚刚改变，或情绪余波仍在。允许下一章直接承接正在发生的行动，也允许安静收在一个改变后的日常细节上。

不要为了“留悬念”添加总结段、作者式预告、突然敲门、身份揭示或半句断章。结尾只需留下真实的下一步状态；如果本拍已经完成且没有新的行动压力，正常收束也合法。

## 细纲验收

- 第一拍必须承接上一章的真实后果，不能凭空换主线。
- 中间至少一拍要让人物的行动引出更难的新局面；如果所有拍都只是解释已有信息，回到当前弧重拆目标。
- 最后一拍必须完成本章局部回报、把代价落地，或让当前动作自然停住。跨章事件不要求在本章形成完整答案，也不要求额外制造悬念句；下一步状态可以直接承接在正文动作中。
- 各拍的“状态落点”合起来至少覆盖两项状态变化；同一变化不能在多拍里换说法重复计算。
- 删除任一拍后，若后文状态、因果或人物选择完全不受影响，该拍没有章节职责，应删除、合并或改写。
- 若细纲只有两拍且第二拍只是第一拍的延长，优先拆章或把目标改成更明确的阶段回报；不靠加环境、回忆和闲聊拉长。
- 这一章若有揭示，先回答四句：用的是前文已经出现的事实，或这一拍里用行动让读者自己对上；它改变的是一个已经做出的选择的代价；不用角色演讲把答案讲完；同一章只留一个会改情感判断的揭示，其余降成信息。答不上来就还不是反转，不要为了转折硬加。

## 使用方式

先填写写前卡，再填细纲；写正文时按拍推进，但允许人物在过程中作出符合正史的新反应。新反应若改变本章目标、回报或结尾，先重排后续拍，再继续写。正文完成后对照细纲删去已被行动证明的解释，并将实际发生的变化写入状态文件；未发生的计划不能提前写进正史。
