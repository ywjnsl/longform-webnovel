# 篇幅模式

## 先选模式

`project.json.storyMode` 只使用两个值：

- `serial`：默认长篇连载。每章以约 2500 个有效内容字符作为起始估算和节奏异常信号，不是硬性配额；未来 5–10 章滚动规划，执行 3/5/15 章节拍。
- `fanqie-short-story`：番茄短故事。把作品视为一次完整的有限叙事，可写成一个完整文本或少量连续分节，不把长篇循环机械压缩。

旧项目没有 `storyMode` 时按 `serial` 读取。模式改变会重写故事合同、节奏和结局预期，属于必须由作者确认的重大决策。

## 番茄短故事合同

建项前确认或明确标记以下信息：

- 一句话主承诺：读者最终要获得哪一种核心答案、情绪或命运结果；
- 目标总有效字符数与预计分节数；尚未决定时可以留空总字数，但写正文前必须形成可执行范围；
- 主要矛盾及其结局条件；
- `endingType`：默认 `closed`，只有作者明确要求时才用 `open`；开放结尾也必须结束主要行动和情绪问题，不能只截断；
- 内容边界、目标读者、语言风格、终选书名和封面提示词。

番茄作家帮助中心把“短故事”作为独立作品管理入口，并与长篇/短篇小说区分。平台当前投稿门槛、分类和字数统计可能调整；发布前以当时作家后台和官方创作宝典为准，不把本文档的创作目标当成永久平台规则。

## 有限结构

用全文百分比规划，不强制第 3/5 章节拍：

| 位置 | 必须完成的工作 |
|---:|---|
| 前 10% 左右 | 开局扰动：核心异常、欲望或压力已经发生 |
| 20%–30% | 不可逆选择：主角主动进入主要冲突并付出第一笔代价 |
| 45%–60% | 中点翻转：认知、关系、目标或胜负条件实质改变 |
| 75%–90% | 决定性对抗：主要矛盾进入不可回避的解决 |
| 100% | 结局收束：兑现主承诺，回收关键铺垫，交代选择后果 |

分节很少时，同一节可以承担多个位置；合并后必须形成一个完整因果动作，不能连续堆反转。`plan_cadence.py` 会把这些位置映射到预计分节，并只为需要明确兑现的结构位置建立爽点账本。

## 场景预算

- 只保留一个主承诺和一个主要矛盾。副线必须直接加压、误导、映照人物选择或参与结局兑现。
- 每个场景至少完成一项：推进冲突、揭示有效信息、迫使人物选择、兑现此前等待；最好同时完成两项。
- 伏笔必须在全文内有回收位置。无法影响结局的谜团、设定和人物履历优先删除。
- 回报频率服从阅读体验，但短于五节时不补造“第 3 章小爽点、第 5 章大爽点”。用不可逆选择、中点翻转、决定性对抗和结局代替机械周期。
- 结局追求“回看时合理、初读时不完全预料”。惊讶必须来自已给出的因果和人物选择。
- 默认不留续作诱饵。作者明确选择开放结尾时，可以保留余韵或次级未知，但主承诺必须兑现。

## 人物与配角

短故事通常只保留 1–3 名真正影响主线的核心配角。配角仍需拥有自己的欲望、信息和选择，弧光可由事业、信念、责任、家庭、友情、师徒、竞争、债务、复仇、求生、归属或爱情驱动；但不为满足账本而强迫每人完成独立五幕弧。

判断标准是：配角的选择是否改变主角可选方案、主要矛盾或结局代价。只承担功能的一次性人物使用 `cameo`，不另开无法收束的支线。

## 状态与完结

短故事继续使用正史、线索、爽点、配角和审稿文件，但降低管理负担：

- `planning/rolling-outline.md` 覆盖全部剩余分节，不维护未来 5–10 章窗口；
- `shortStory.status` 从 `planning` 进入 `drafting`，全文完成并通过终审后改为 `complete`；
- `plannedSections` 是当前结构合同和叙事职责清单，不是字数配额。需要增减时先判断是否改变结局与核心体验；重大改变先问作者。若一节只能靠重复对白、重复解释或无后果反转来达到长度，优先增加一个来自既有行动后果或必要未闭合线索的新分节，并为它写明独立的因果职责；若增节改变主承诺、结局类型或主要矛盾，走重大决策确认流程。增减分节后同步更新 `planning/rolling-outline.md`、爽点账本、状态快照和 `project.json` 中的 `shortStory.plannedSections`。
- 标记 `complete` 前，主要线索必须 `resolved` 或 `transformed`，最后一节必须交付结局级 `major` 回报，并完成绑定全文哈希的 `reviews/final-review.json` 外部读者终审；
- 完结终审额外检查主承诺兑现、伏笔回收、因果闭合、人物选择后果、标题照应和开放结尾边界。
- 标题、首屏和试读节点若承担主要分发入口，写作前与完稿后都按 [short-story-information-flow.md](short-story-information-flow.md) 回读；这只是入口质量检查，不是流量保证。

不要在已标记 `complete` 后自动生成下一章。续作、新篇或改成长篇都属于新的重大决策。

## 建项命令

```bash
python3 <skill-dir>/scripts/init_project.py \
  --path <项目目录> \
  --title <书名> \
  --style <风格标识> \
  --mode fanqie-short-story \
  --target-total-chars <目标有效字符数> \
  --sections <预计分节数>
```

`--target-total-chars` 是作者的创作目标，可在尚未决定时省略；它不代表番茄平台的固定上下限。`--sections` 默认 5，可根据故事结构调整。
