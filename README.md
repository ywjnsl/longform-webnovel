# Longform Webnovel

一个面向中文长期网文连载、短中篇完整小说与番茄短故事的 Codex Skill。它把小说作为持续演化的项目来管理，而不是一组彼此独立的提示词或章节。

默认长篇按卷写。每一卷一条贯穿线，卷中可开支流完善它，也可为后卷留伏笔。一段标明贯穿或支流，到约 2500 字切下一章，直到这段事完结。贯穿线落地后停止，不自动写下一卷。细纲不摊成正文。短故事模式使用全文比例结构并明确完结，篇幅按场景职责保持弹性。题材不固定，支持新书策划、短故事、长期续写、旧稿导入、卷纲扩展和结构修订。

## 工作范围

- **试写、审读、局部修改候选**：直接处理正文和必要前后文，不要求先建项目、定名或做封面。候选保存在工作稿，不自动进入正史。
- **正式入库**：采用新章或修订稿时，执行完整审稿、正文哈希绑定、状态同步与提交恢复流程。可以先用暂定书名，未完成包装保留 `unconfirmed` 并提示，不阻断正文入库。
- **发布准备**：按请求处理书名、简介、封面或完整投稿包；整套完成后才标记包装为 `active`。不把未做的检索或确认写成完成。

写法参考按具体问题选用。规则交涉的条件、原件和收尾诊断不用于强制所有场景；直接情绪、心理、抒情和评论型旁白按作品声音判断。同会话切换审稿视角属于多视角复核，不能宣称实现独立上下文或真实读者验证。

## 主要能力

新增 `novella` 短中篇模式：默认目标约 5万字（参考 3万–10万字，可调整），先确定结局、代价和人物归宿，再规划全书阶段与必要副线。正文连续写到约 2500 字切章，阶段可跨章，不按章号安排转折，不要求固定章数。每章正式入库时执行自然度检查与全部审稿，有成立问题才定向改稿，完结需通过全文终审并满足明确字数下限。详见 [短中篇规则](skill/longform-webnovel/references/novella.md)。

```bash
python3 skill/longform-webnovel/scripts/init_project.py \
  --path ./我的短中篇 --title 我的短中篇 --mode novella \
  --style fanqie-clean --target-total-chars 50000
```

若明确要求至少 3万字，另加 `--min-total-chars 30000`；目标字数与最低字数分别记录，章节数由实际推进决定。

- 使用故事合同、滚动章纲和状态账本维持跨会话连续性。卷纲先写不可逆终点再倒推；每一段事件用一句话写它让哪件已有的事更难，或付清哪一笔旧账；不预分各章剧情。
- 长篇按贯穿线段序安排兑现，大约三段一次小兑现、五段一次大兑现，不绑定章号；短中篇按全书阶段和实际行动交付回报。
- 番茄短故事不机械套用 3/5 章循环，改用开局扰动、不可逆选择、中点翻转、决定性对抗和结局收束。
- 在重大方向变化前询问作者，其余章节级选择自主完成。
- 发布准备时筛选有辨识度的书名和简介，保存公开检索记录；封面同时交付三种差异化书名字效方向、一次成图词、纯底图词和标题区域重绘词。画面写一种构图和前、中、远三层，只展示入口冲突。简介、书名、封面和前 300 字答应同一件事。
- 支持语言风格档案和知名作者公开写作手法的参数化转译，不复刻标志性表达。
- 为核心配角维护独立目标、选择、后果和非主角中心关系。
- 角色以项目内 skill 维护情绪、知情范围与意图；写章前由法则裁判否决非法行动，弧可跨多章，切章不重置事件或限制推进格数。失败和改路也算交付。
- 可选保存带日期、URL、样本和置信度的公开市场观察。
- 短故事市场研究强制区分长篇与短故事样本，并可在开书前扫描历史项目同质化风险。
- 支持从参考短故事提取结构、情绪与叙事机制，生成非换名复述的新故事，并检查连续原文复用和禁用专名。
- 支持对“主角永远正确、证据过齐、人物同声、流程过满”等模板感做证据化自然修订，不使用故意病句或去 AI 词表。
- 对 14 字以上长句做精确重复门禁，并检查高相似复述、副词簇、工整回环和机械三拍；可保存朱雀逐段标红作为非阻断编辑证据。
- 为追妻、追夫、火葬场、破镜重圆和追而不得题材检查旧情基础、伤害累积、醒悟触发、补偿代价与最终选择，不强制复合或新增伴侣。
- 保存发布后展现、阅读、完读与互动窗口，按样本量诊断流量漏斗，不把本地阈值冒充平台规则。
- 每次新写或修改章节正式入库时都执行语言风险扫描、自然度审稿、编辑审稿和目标读者模拟，并在改稿后重新绑定正文哈希；试写和未采用候选按轻流程检查。
- 番茄短故事默认按公开签约质量检查空转、机制是否运行和收口是否做完；人物按角色卡核对选择一致性、胜利代价、身体情绪和对白辨识。
- 新书开篇检查设定微创新、首屏看点和无效花活；写章核对战力/金钱/规则与时间线，避免出戏。
- 筹备按需读取参考，沿用当前事件的写前卡；正文使用精简上下文。改已提交正文时先分清不改、小改还是大改，避免越改越乱。
- 使用正文 SHA-256、隔离预览、备份与回滚保证章节和状态原子提交。

正式正文入库流程为：连续初稿 → 结构与人物选择检查 → 保存语言改稿基线并冻结事实 → 真人感检查（有成立问题才局部改写并逐处取舍）→ 重复、自然度、编辑与读者审稿 → 状态提交。初稿允许完整心理、主观判断与必要叙述；动作步骤、感官数量和对白轮次不设固定配额。长篇与短中篇在事件或阶段上检查升级、回报和状态变化，不强塞进每个约 2500 字的切片。改后对照原稿声音，人物更同声、情绪变薄或变成流程说明时恢复对应表达；结构调整另存最初版本，披露到最终稿的总字数变化，避免重置基线掩盖缩水。无具体问题时保留原文；“更具体、更顺、更口语”不足以单独启动改写。改文是候选，按原先的阅读问题比较收益与代价，无明确收益就恢复原段，不能凭保留率或扫描通过认定改后更好。不靠新增场面、随机句式或故意错字制造真人感。已有朱雀逐段报告时冻结未标红段落。改后低于原稿90%时复核有效内容与声音，比例只作检查信号；误删才恢复，删除重复内容可以接受变短。作者明确的全文最低篇幅仍须满足。

朱雀 PDF/截图可作为外部编辑信号：先核对送检版本，记录报告哈希与分段索引，再凭阅读证据局部处理。有复测报告时按文本范围对齐比较；未复测如实记录，不把本地扫描当检测结果，也不追逐总体百分比。

报告中 AIGC 值最低的片段可列为候选声音样本。只有作者确认读感后，才提取其中的叙事距离、对白处理、动作细节和收尾方式写入风格档案；长篇按章或场景类型调用，不把低值直接当成人类范文，也不复制原句或事件。

语言风险扫描只提供编辑调查信号，不判断文本是否由 AI 创作，也不输出作者身份概率。

## 安装

克隆仓库后，将 Skill 目录复制到 Codex 默认 Skill 位置：

```bash
git clone https://github.com/ywjnsl/longform-webnovel.git
cp -R longform-webnovel/skill/longform-webnovel ~/.codex/skills/
mkdir -p ~/.cursor/skills/longform-webnovel
cp longform-webnovel/cursor-skill/SKILL.md ~/.cursor/skills/longform-webnovel/SKILL.md
```

重新打开 Codex 任务后，可直接调用：

```text
$longform-webnovel 帮我策划一部可以长期连载但不注水的中文网文。
```

## 仓库结构

```text
skill/longform-webnovel/   可安装的 Codex Skill
cursor-skill/              Cursor 发现用入口，指向 Codex 目录
tests/                     集成与结构测试
.github/workflows/         GitHub Actions
```

运行测试：

```bash
python3 tests/check_skill.py
python3 tests/test_longform_webnovel.py
python3 skill/longform-webnovel/tests/test_naturalness_gate.py
python3 skill/longform-webnovel/tests/test_repetition_audit.py
python3 skill/longform-webnovel/tests/test_chapter_cut.py
python3 skill/longform-webnovel/tests/test_draft_checkpoint.py
```

运行时只依赖 Python 标准库。结构检查验证资源和链接，不固定编辑文案与示例原句；已有模型执行产物可用 `tests/check_behavior_artifacts.py` 核对引号、候选边界、正式提交和无损切分。脚本不代替模型执行，检查通过不代表文学质量得到证明。跨题材和不同任务规模的行为评估见 [行为评估用例](tests/skill-behavior-cases.md)，需实际执行并保留产物后才能报告结果。

## 创作边界

- 公开市场研究用于理解读者需求和差异化空间，不授权复制样本作品。
- 参考再创作只迁移抽象机制，不逐段同义改写，不复用人物专名、独特物件、事件链、关键场面或结局揭示。
- 可以借鉴公开可描述的叙事手法，但不直接模仿在世作者的标志性措辞。
- “长期扩展”依靠正史和状态文件实现，不承诺脱离上下文限制的无限生成。
- 短故事的总字数、分类和投稿条件以发布时的番茄作家后台为准，Skill 不硬编码可能变化的平台门槛。
- 自动审稿不能替代作者判断；严重风险只能由作者通过明确决策记录接受。
